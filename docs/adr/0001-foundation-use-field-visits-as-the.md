# 0001. Foundation: Use field_visits as the Dart package name and 'Field Visits' as the localized display name; the appTitle ARB key is the single source of visible text

## Status

Accepted · 2026-10-21

## Context

Build of field_visits (foundation · from STACK.md). Builds the Flutter foundation for an offline-first visits app: a manifest, strict analysis, localization configuration, a minimal MaterialApp that displays the localized project name, one smoke test, and the local/CI tooling needed to run the same quality gates. The app boots through lib/main.dart, which mounts FieldVisitsApp from lib/app/app.dart; the only visible text comes from the generated AppLocalizations for the appTitle key. No database, sync engine, repository, or feature screen is included yet; core/, features/, and data/ locations from STACK.md stay empty until the domain build. Makefile, Lefthook, GitHub Actions, and Renovate keep formatting, linting, tests, and dependency updates consistent. README.md is the entry point for setup and deferred scope.

## Decision

Architecture: Foundation only. lib/main.dart is the composition root and the only place that calls runApp; lib/app/ owns the root MaterialApp and later router/theme; lib/l10n/ owns the ARB template and generated localization classes. Tooling sits outside the runtime: l10n.yaml and analysis_options.yaml define generation and lint, Makefile exposes the local command surface, lefthook.yml wires local hooks, .github/workflows/ci.yml mirrors the quality gates, renovate.json handles updates, and .env.example documents DATABASE_PATH. Future dependency direction stays presentation -> domain <- data, with core/sync depending on per-feature adapters through interfaces; this foundation imports nothing from core/ or features/.

- Use field_visits as the Dart package name and 'Field Visits' as the localized display name; the appTitle ARB key is the single source of visible text.
- Generate localization into lib/l10n/app_localizations.dart via l10n.yaml with nullable-getter: false; generated localization files are git-ignored and regenerated by setup and CI.
- Keep the foundation free of drift, sync, Riverpod, and feature code; only flutter, flutter_localizations, intl, flutter_test, and very_good_analysis are declared now.
- Use a Makefile as the local command surface and run the same commands explicitly in CI; no CI-only scripts.
- Read future configuration from .env through --dart-define-from-file=.env; .env.example documents DATABASE_PATH, but no database is opened in this foundation.
- Install Flutter stable in CI with a shallow clone and pin the only marketplace action, actions/checkout, to a full commit SHA.
- Lefthook formats staged Dart files and enforces Conventional Commits; tests stay in CI.

## Consequences

- Files created: pubspec.yaml, analysis_options.yaml, l10n.yaml, lib/l10n/app_en.arb, .env.example, .gitignore, lib/app/app.dart, lib/main.dart, test/smoke_test.dart, Makefile, lefthook.yml, .github/workflows/ci.yml, renovate.json, README.md
- Later changes follow these decisions; one that reverses a decision gets a new ADR that supersedes this one.
